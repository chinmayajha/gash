# gash for macOS

A fast, native, from-scratch **bash-compatible shell for macOS**, written in Rust with
zero dependencies. This is a port of [hex2f/gash](https://github.com/hex2f/gash), which
targets Windows/Git Bash; the Windows/MSYS integration was replaced with a POSIX one.

gash parses and runs bash scripts itself instead of wrapping bash. Subshells, `$(...)`
and pipelines of builtins run in-process (cloned shell state and threads), so a script
with many of them does not pay a `fork()` per construct. External programs run normally
with `posix_spawn`/`fork`+`exec` through Rust's `std::process`.

## Status

The differential test corpus in `tests/scripts` was generated by real Git Bash. On macOS
it passes **67/67** runnable scripts (~2,000 labelled cases); scripts that test
Windows-only behavior (MSYS path translation, `.exe` lookup, `/proc/self/fd`) are skipped
on non-Windows hosts. Unit tests cover the parser, expansion, arithmetic, globbing,
patterns, the line editor and completion.

## Building

Requires Rust (any recent stable; developed with 1.99).

```bash
cargo build --release
```

The binary is `target/release/gash`. There are no runtime dependencies beyond the system
C library and the usual `/bin`, `/usr/bin` tools.

## Installing

```bash
install -m 755 target/release/gash ~/bin/gash
```

or copy it to `/usr/local/bin`. `~/bin` is not on the default macOS `PATH`; add
`export PATH="$HOME/bin:$PATH"` to your `~/.zprofile` if you use it. To use it as `bash`
or `sh`, copy it (do not symlink)
under those names in a directory that comes before `/bin` on `PATH`:

```bash
install -m 755 target/release/gash ~/bin/bash
install -m 755 target/release/gash ~/bin/sh
```

gash reports itself under the name it was invoked as. Do not replace `/bin/bash`: macOS
system integrity protection prevents it, and system scripts expect the real bash.

## Using it

```bash
gash                      # interactive shell
gash script.sh args       # run a script
gash -c 'echo hi'         # run a command string
gash -lc '...'            # login shell (sources ~/.bash_profile)
```

Startup files: login shells read the first of `~/.bash_profile`, `~/.bash_login`,
`~/.profile`; interactive non-login shells read `~/.bashrc` (or `--rcfile`).

Flags: `-c`, `-s`, `-i`, `-l`/`--login`, `--norc`, `--noprofile`, `--rcfile FILE`,
`--posix`, `-o opt`, `-O shopt`, any `set` flag (`-e -u -x ...`), `--version`.

Interactive mode provides emacs-style line editing, history (`~/.bash_history`,
`HISTCONTROL`, `!!`, `!$`, `^old^new`, Ctrl+R), and Tab completion of commands, files,
`$variables` and `~` paths. The terminal is put in raw mode with termios; the previous
mode is restored on exit, Ctrl+C and panic.

## Supported bash features

- Full grammar: pipelines, `&&`/`||`, `&`, subshells, groups, `if`/`case` (incl. `;&` `;;&`),
  `while`/`until`/`for`/C-style `for`/`select`, functions, `[[ ]]`, `(( ))`, `time`, `!`,
  here-docs (`<<`, `<<-`, quoted delimiters), here-strings, process substitution, aliases.
- All parameter expansions: defaults/alternates, `#`/`%` trimming, `/` `//` `/#` `/%`
  substitution (with `patsub_replacement` `&`), substrings, case modification, `${!ref}`,
  `${!prefix*}`, `${!arr[@]}`, `@Q @E @P @A @a @U @u @L @K`, namerefs.
- Indexed and associative arrays, `declare`/`local`/`readonly`/`export` with all attributes,
  integer/upper/lower variables.
- Arithmetic with all bash operators, bases (`0x`, `0`, `N#`), assignment operators.
- Globbing with `nullglob`, `failglob`, `dotglob`, `nocaseglob`, `globstar`, `extglob`,
  `GLOBIGNORE`; brace expansion including sequences.
- `set -euxo pipefail`, `set -C`, `shopt` (all bash option names), traps (`EXIT`, `ERR`,
  `RETURN`, `INT`, signals to self), `getopts`, `read` (all flags), `mapfile`, `printf`
  (incl. `%q %b %(fmt)T`, `-v`), `echo`, `test`, `type`, `command`, `hash`, `eval`,
  `source`, `exec` (incl. fd redirection), `pushd`/`popd`/`dirs`, `jobs`/`wait`/`kill`/`fg`,
  `alias`, `history`, `compgen`, ...
- Bash's error-recovery rules (arithmetic and substitution errors discard the current
  command line; `${x:?}` and `set -u` exit the script).

## Differences from bash

- **No `fork()` for shell constructs**: subshells, `$(...)` and pipeline stages run
  in-process (threads with their own variables, cwd and fd table). `$BASHPID` in a
  subshell is a synthetic number, and `kill` of a subshell's `$BASHPID` only works for
  signals delivered to itself.
- **Process substitution** `<(cmd)` / `>(cmd)` uses temporary files rather than pipes, so
  `<(cmd)` runs `cmd` to completion first (not streaming).
- **Job control**: background jobs, `jobs`, `wait`, `fg` (waits) and `kill` work; there is
  no Ctrl+Z stop.
- **File descriptors > 2** work inside the shell (`exec 3>file`, `>&3`) but are not passed
  to external programs.
- Strings are UTF-8 internally: `$'\xff'`-style bytes ≥ 0x80 in variables are approximated;
  `printf`/`echo -e` write raw bytes correctly.
- The shell does not source `/etc/profile` or `/etc/bash.bashrc`.

## Testing

```bash
cargo test                                        # unit tests + compat suite
GASH_COMPAT_FILTER=015 cargo test --test compat   # one script
GASH_COMPAT_JOBS=8 cargo test --test compat       # parallel
```

Expected outputs are Git Bash-derived; `tests/regen_expected.ps1` regenerates them on
Windows. MSYS-only scripts are listed in `WINDOWS_ONLY` in `tests/compat.rs` and skipped
elsewhere.
